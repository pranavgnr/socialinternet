# Creators 101 V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the free, creator-first V1: landing page with trending-niche bubbles, Google sign-in, a daily credit pool, a grounded chat assistant, and a vendor canary, on top of the existing `lib/` engine.

**Architecture:** Keep `lib/` (harvest, niche, plan, providers) unchanged in behaviour. Add Postgres for new state only (users, sessions, credit ledger, chat, trending niches, creator profiles). Plans, ideas and weekly digests stay in per-visitor JSON, linked to the signed-in user (see Task 3). New UI is a landing page, bubbles, chat panel and sign-in.

**Tech Stack:** Next.js 16.4.3 (`cacheComponents` on), React 19, Tailwind 4, `pg`, `arctic` (Google OAuth), `@electric-sql/pglite` (tests only), `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-02-creators-101-v1-design.md`

## Global Constraints

- Read the relevant guide in `node_modules/next/dist/docs/` before writing any Next.js code (AGENTS.md). Pages that read cookies or the DB sit behind `await connection()` or a `<Suspense>` boundary, as `app/page.tsx` and `app/weekly/page.tsx` already do.
- No test runner exists. Tests are `scripts/test-*.ts`, compiled with `npx tsc <file> --module commonjs --target es2022 --moduleResolution node --outDir .tmp-build --skipLibCheck --esModuleInterop --lib es2022,dom --types node`, then `node --test .tmp-build/scripts/<file>.js`. Task 1 adds `npm run test:file -- <name>` wrapping this.
- DB tests run on PGlite with the same SQL files as production. Production uses `DATABASE_URL`.
- Daily credit pool resets at midnight IST (Asia/Kolkata). Unit: whole credits, integers.
- Initial prices (1 credit ≈ $0.01, from measured vendor cost: niche ≈ $0.06, handle ≈ $0.055): cached read 0, fresh niche 6, fresh handle 6, chat message 1, daily free pool 15. All overridable by env (`CREDIT_COST_NICHE`, `CREDIT_COST_HANDLE`, `CREDIT_COST_CHAT`, `CREDIT_DAILY_FREE`).
- Anonymous visitors may open cached niches only. Any call that would spend vendor money requires sign-in.
- Chat answers only from the user's analysed data and refuses everything else.
- Creator-facing copy speaks to the creator, never to a brand. Per-user data is private by default.
- Never print a number for an account that was not read (existing product rule). Use `lib/plain.ts` for any user-visible string.
- Apify free-plan price is $2.70 per 1,000 results.
- Commit after every task. Run `npx tsc --noEmit` before each commit.

## Review Focus

1. Two requests spend the last credits at the same instant: exactly one succeeds, balance never negative (Task 2).
2. A fresh read that fails or turns out to be a cache hit must not keep the charge (Task 4).
3. Spend near midnight IST lands in the correct day, and the pool resets once (Task 2).
4. Handle input in any form (`@Name`, uppercase, full instagram.com URL, trailing slash, spaces) resolves to one canonical handle (Task 6).
5. A chat message that tries to override the rules, or asks something unrelated, gets the refusal and costs no credit (Task 7).
6. OAuth callback with a missing, reused or mismatched `state` is rejected and creates no session (Task 3).
7. Zero cached niches, or a cron that failed, still renders the landing page with a working search (Tasks 5, 6).
8. Signed-in user with no plan asks the chat anything: told to analyse a handle first, not given a made-up answer (Task 7).
